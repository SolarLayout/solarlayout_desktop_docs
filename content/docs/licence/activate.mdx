---
title: Activate this device
description: Get free access for this device from the License / Subscription window, complete it in your browser, and confirm it automatically.
---

Activation ties access to **this device** — there is no file to send, receive,
copy or keep safe. Open the **License / Subscription** window, copy this
device's Device ID, request access, and complete it in your browser. Switching
back to the window confirms it automatically.

You can also see this at a glance without opening the window: the top toolbar
always shows an access-status chip. On a device that has never been activated
it reads **●  No active access**, with a **Get Free Access** button right
beside it that does exactly what the window's button does.

Until access is active, **Generate Layout** — and every export, plus the SLD
and BOM tools — won't run. Everything else in the application works. See
[How access works](/docs/licence/overview) for the full list of what stays
free.

<Steps>

<Step>
### Open Help ▸ License / Subscription…

The **License / Subscription** window opens. On a device with no active
access, the status headline reads **✗  No access**, with the message *"No
active access for this device. Click 'Get Free Access' to get started."*
beneath it, followed by *"Layout generation is disabled until your access is
active."*

Below that: the read-only **Your Device ID** field, labelled *"This Device ID
identifies this computer to SolarLayout (it matches Settings ▸ System ▸ About
▸ Device ID):"*, with its **Copy** button, then **Get Free Access**,
**Contact Us**, **Refresh** and **Close**.

<Screenshot id="licence-no-licence" />
</Step>

<Step>
### Copy the Device ID

Click **Copy** beside the Device ID field rather than reading the value off
the screen. It goes straight to the clipboard. The Device ID is the key —
there is nothing else to install, load or back up.
</Step>

<Step>
### Click Get Free Access

The status headline changes at once to **⏳  Waiting for activation**, and
your browser opens to the activation page for this device
(`https://solarlayout.app/desktop/solarlayout?device=<DeviceID>`).
</Step>

<Step>
### Complete activation in your browser

Finish activation for this Device ID on the page that opened.
</Step>

<Step>
### Return and confirm

Switch back to the **License / Subscription** window. It re-checks
automatically whenever it regains focus — no need to click anything. You can
also click **Refresh** to check immediately.

A device with active access shows **✓  Active**, with the sub-text *"You have
access until &lt;Month DD, YYYY&gt;."*, and **Access Details**, **Refresh** and
**Close** in place of the earlier buttons.

<Screenshot id="licence-valid" />

**Generate Layout** now works. Go to
[Your first layout](/docs/first-layout).
</Step>

</Steps>

<Callout type="info">
If the status reads **✗  No access** with a message about access having
ended or been revoked, **Get Free Access** will not help:

- *"Your access has ended. Contact SolarLayout to purchase a licence."*
  (expired)
- *"Access has been revoked. Contact SolarLayout."* (revoked)

See [Licence problems](/docs/licence/troubleshooting) or contact SolarLayout
at [sales@solarlayout.app](mailto:sales@solarlayout.app). **Contact Us** in
the window opens the same page
([solarlayout.app/contact](https://solarlayout.app/contact)).
</Callout>

## If you try before activating

Clicking **Generate Layout** (or an export, or the SLD or BOM tools) before
access is active shows a **Subscription Required** dialog: *"Layout
generation is locked."*, then the reason, then *"Open Help ▸ License /
Subscription… to view your Device ID and start your free trial."* The
**License / Subscription** window then opens itself so you can act on it.

<Screenshot id="licence-blocked-generate" />

## Working offline

A successful check is cached, so the application keeps working for up to
three days without an internet connection. If it cannot reach the server and
has no usable cached result, it reports *"Could not verify access — connect to
the internet and try again."*

## Updates, reinstalls and other accounts

**Updates and reinstalls do not require reactivating.** Access is checked
against the server and tied to the device, not to a file on disk, so it
survives reinstalls and updates automatically. See
[Updates and reinstalling](/docs/install/updates).

**A second Windows user account on the same PC has the same Device ID.**
Access carries over to that account without doing anything further.

Access to SolarLayout Desktop is tied to **this device**, not to a licence
file. Help ▸ **License / Subscription…** opens the window that shows this
device's status and requests access for it — there is no file to install,
copy, back up, or keep safe. The Device ID is the key, and status is checked
online with the server.

You don't need to open that window just to check status, though — a small
access-status chip is always visible in the top toolbar: **● Active — until
&lt;date&gt;**, **● No active access** with a **Get Free Access** button
beside it, **● Access expired** or **● Access revoked** with a **Contact Us**
button, or **● Access status unavailable** if the last check failed. The app
version is shown in the status bar at the bottom of the window.

The application opens fully usable regardless of that status. Access only
matters once you ask it to generate a layout or hand you a result.

## What needs this device active

| Action | Needs active access |
| --- | --- |
| **Generate Layout** | Yes |
| Every export (PDF, KMZ, DXF, and the rest) | Yes |
| The SLD tool | Yes |
| The BOM tool | Yes |

Because almost everything downstream is computed *from* a generated layout,
a device without active access is in practice limited to exploring the
inputs — reading and changing every field in the panel, loading a boundary
file, and opening every menu, the in-app guide, and the **License /
Subscription…** window itself.

Clicking **Generate Layout** without active access opens a **Subscription
Required** dialog instead of a layout: *"Layout generation is locked."*,
followed by the reason for this device, then *"Open Help ▸ License /
Subscription… to view your Device ID and start your free trial."* The
**License / Subscription** window then opens itself.

## The License / Subscription window

The window's status headline reports one of three states:

- **✓ Active** (green), with *"You have access until &lt;Month DD, YYYY&gt;."*
  underneath.
- **✗ No access** (red), with the reason for this device followed by
  *"Layout generation is disabled until your access is active."*
- **⏳ Waiting for activation** (amber), shown right after you click **Get
  Free Access**, until the app confirms it.

<Screenshot id="licence-no-licence" />

Below the status is **Your Device ID** — a read-only field labelled *"This
Device ID identifies this computer to SolarLayout (it matches Settings ▸
System ▸ About ▸ Device ID):"*, with a **Copy** button beside it. The Device
ID is the Windows registry `MachineGuid` — the same value Windows itself
shows under Settings ▸ System ▸ About ▸ Device ID.

The buttons on offer depend on the state:

- While active: **Access Details**, which opens the same web page as
  activation, for this device.
- While not active: **Get Free Access** and **Contact Us**.
- Always: **Refresh** and **Close**.

## Getting access

Click **Get Free Access** and the application opens your browser at the
activation page for this device. Complete activation there, then switch back
to the **License / Subscription** window — it re-checks automatically and
the headline flips to **✓ Active**.

**Contact Us** opens the SolarLayout contact page in your browser, for
questions or to arrange paid access. [Activate this device](/docs/licence/activate)
walks through the full flow.

## Access states

The server reports one of four states for this device: `active`, `expired`,
`revoked`, or `none`. Each shows its own reason in the **License /
Subscription** window:

| State | Reason shown |
| --- | --- |
| Expired | *"Your access has ended. Contact SolarLayout to purchase a licence."* |
| Revoked | *"Access has been revoked. Contact SolarLayout."* |
| None | *"No active access for this device. Click 'Get Free Access' to get started."* |

## Working offline

When this device can't reach the server, a good check it already made is
cached, and the application keeps working under that cached status for up to
3 days before it needs to check in again. If it can't reach the server and
has no usable cached check, it reports *"Could not verify access — connect
to the internet and try again."*

## Updates, reinstalls, and other accounts

Access is server-side and tied to the device, not stored in a file, so it
survives reinstalls and application updates automatically — there is nothing
to re-load. See [Updates and reinstalling](/docs/install/updates).

A second Windows user account on the same PC has the same Device ID, so
access carries over to it too — unlike a per-user file would.

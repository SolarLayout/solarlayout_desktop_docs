Find the symptom below and read the entry under it. Each one says what the
application is doing, why, and which input or switch to change.

Licence messages are not here. Every message the licence check produces has its
own entry in [Licence problems](/docs/licence/troubleshooting).

## Three things that explain most surprises

1. **A missing figure is usually a step you have not run.** Cables and energy are
   separate, opt-in calculations, and a `—` in the Summary view means not
   computed.
2. **Missing tables are usually a subtraction that is switched on.** The boundary
   is shrunk by the perimeter road, then obstructions, corridors, terrain
   exclusions and equipment footprints come out of what is left.
3. **Greyed-out exports usually mean an input changed.** The layout remembers
   the inputs it was generated from; once one differs, the results are out of
   date and nothing exports until you regenerate.

## Starting up and licensing

<Accordions>
<Accordion title="Generate Layout is disabled, or opens the licence window">

Two different causes, told apart by the hint under the button. If the hint
reads *"Select a boundary file on the Site tab to generate a layout."*, no
file has been chosen yet: open the **Site** tab and use **Browse…** or **Open
sample site** in the **Input Boundary File** card, and check the line under the
field reports the boundary summary once the file is read.

If the button is enabled but clicking it opens **License / Subscription**
instead of generating, this device's access is not active. Check the access
chip in the ribbon: it reads **● Active — until \<date>** when you are
covered; **● Access expired** or **● Access revoked** otherwise; and with no
access at all the chip is replaced by a **Get Free Access** button. See
[How licensing works](/docs/licence/overview) for what is checked, and
[Activate your licence](/docs/licence/activate) if you have never got access
for this device.

</Accordion>
<Accordion title="An unexpected error occurred, but the application will keep running">

Something failed in a way the application did not expect. It catches the failure,
reports it with that exact message, and **keeps running** — your inputs and your
layout are still there. It is a report, not a crash.

Save the session with **Save project** first, then retry the step, changing one
input at a time to find which one the failure depends on. The details are
appended to a file named `solarlayout_error.log` in the Windows temporary folder —
type `%TEMP%` into the address bar of File Explorer to get there. Include it when
you report the problem: see [Getting help](/docs/support).

</Accordion>
</Accordions>

## Loading a boundary file

<Accordions>
<Accordion title="The file was refused, or a boundary is listed as a problem">

A plant boundary must be a **closed polygon** — first and last ring coordinate
identical. When one is open, the **Check boundaries** window lists each problem
boundary with the gap it found, every row ticked under **Leave out**. The
primary button, **Continue without \<n\>**, carries on with the others; **Fix in
Google Earth first** closes the window so you can repair the file. Prefer
fixing the file — leaving a boundary out leaves out the whole plot, so its
capacity is lost, and an unticked open boundary is kept as it is and may
produce a wrong layout. Close the ring in the tool you drew it with, save, and
load it again. The rules are in
[Boundary file requirements](/docs/inputs/kmz-requirements).

</Accordion>
<Accordion title="Tables have been placed on a pond or a building">

A polygon inside a plant boundary is subtracted from the usable area, so tables on
top of one mean the feature was not read as an area inside the plant. Check:

1. **Is it inside the boundary?** Every feature has to lie inside a boundary
   polygon. One that is not contained in a boundary is read as a top-level
   polygon — which is what a plant boundary is.
2. **Is it a closed polygon?** A shape drawn as a path is a line feature, and a line
   feature is buffered as a corridor rather than treated as an area.
3. **Is it named so it can be classified?** Classification is by **name
   keyword**, case-insensitive: `Pond`, `Lake`, `Reservoir`, `Water body`,
   `Wetland`, `Marsh` or `Swamp` is read as water, while a polygon with no water
   keyword is still kept clear but as a generic obstruction — so a misnamed pond
   is drawn and reported as an obstruction rather than as water.

</Accordion>
<Accordion title="An obstruction in the file had no effect">

The polygon lies outside the plant boundary, or crosses its edge. Only polygons
**fully contained** within a boundary become obstacles; one that is not contained is
treated as a boundary in its own right. Open the file in Google Earth and check the
obstruction sits wholly inside the boundary. If it genuinely straddles the fence
line, clip it to the boundary, or draw the exclusion by hand after the run from
the **Tools** tab — see [Obstructions and exclusions](/docs/layout/obstructions).

</Accordion>
<Accordion title="A pond or a transmission line in my CAD drawing was not kept clear, or was treated as a plain obstruction">

A CAD drawing is classified by **layer name**, not by the entity's own name or
a text label beside it. A pond drawn on layer `0` is a generic obstruction —
kept clear, but not water; a transmission line drawn as an open polyline on a
layer with no line keyword in its name is ignored altogether, because only
closed shapes are read on an unnamed layer. Rename the layers in the CAD
program — `POND`, `TL`, `ROAD`, `BUILDING` — and load the file again. A circle,
a spline or an arc is never read, whatever the layer. The keyword lists are in
[CAD drawing boundaries](/docs/inputs/cad-boundary).

</Accordion>
<Accordion title="Energy is refused for a CAD drawing or an image continued as Layout only">

A CAD drawing or an image carries no guaranteed position on Earth, so the
**Site reference** window asks where it sits when you load it. **Continue with
layout only** leaves the location **unknown**: **Calculate Energy** is
disabled, and its tooltip, the Yield tab's status line and the Energy view all
read *"Energy yield is off: the site's location is unknown (layout only)."*
There is no sun position without a site, so there is no energy estimate.

To calculate energy, click **Browse…** on the Site tab and pick the same file
again. In **Site reference**, choose **Drawing's coordinates** and pick the UTM
zone if the drawing was made in UTM, or **Place by latitude and longitude**,
type the latitude and longitude of the centre of the site, and click **Place
the drawing here**. Then generate again. A Google Earth file carries its own
coordinates and never has this problem. See
[A CAD drawing as the boundary](/docs/inputs/cad-boundary) and
[An image as the boundary](/docs/inputs/image-boundary).

</Accordion>
<Accordion title="No KMZ for a CAD drawing placed as Layout only">

On a site continued as layout only the menu item reads **Export KMZ — location
unknown** and is greyed out; its tooltip reads *"The site's location is
unknown (layout only), so a KMZ would put the plant in the wrong place."*
**Satellite** is refused for the same reason, with *"Satellite imagery needs
the site's location."* The CAD drawing export is unaffected: it is written in
the drawing's own coordinates.

The fix is the one in the entry above — pick the file again and say where the
drawing sits — then generate again and export. See
[Google Earth export](/docs/exports/kmz).

</Accordion>
<Accordion title="No automatic tilt or row pitch on a drawing continued as Layout only">

Automatic tilt and row pitch are derived from the site latitude, and a site
continued as layout only has one only if you typed it into the optional
**Latitude** field in **Site reference**. Without it, give the tables their
tilt and pitch yourself: on the **Array** tab tick both **Override tilt angle**
and **Override row pitch**, type the values you want, and generate. Or pick the
file again and enter a latitude. Building-shadow clearance also needs the
latitude. See [Spacing and tilt](/docs/inputs/spacing-and-tilt).

</Accordion>
</Accordions>

## The layout

<Accordions>
<Accordion title="No tables were placed, or far fewer than expected">

The usable area is what is left after a series of subtractions, and a table is
placed only where it fits **entirely** inside it. Work through them in the order
they are applied, switching each off in turn to see what it cost you.

| Step | The input behind it | How to test it |
| --- | --- | --- |
| Perimeter road | **Perimeter road width** on the Site tab, default 6.0 m | Set it to 0 and regenerate |
| Obstructions and water | Polygons in the boundary file, plus anything drawn by hand on the Tools tab | Compare against the file in Google Earth |
| Transmission corridors | **Transmission line corridor**, default 15.0 m per side | Set it to 0 and regenerate |
| Terrain exclusions | **Avoid steep ground** under Topography | Untick it and regenerate |
| Structure shadows | **Clear tables in shadows** under Structures & Shadow, on by default | Untick it and regenerate |
| Lightning arresters | **Place Lightning Arresters**, off by default | Untick it and regenerate |
| Street lights | **Place street lights**, off by default | Untick it and regenerate |

Two further causes on a narrow or irregular plot. **The table is too big for the
ground:** a long table cannot fit a narrow strip at all, so the strip stays empty —
reduce **Modules per row**, or tick **Add half tables** on the Array tab. **The
edges are diagonal or curved:** tick **Maximize placement**. Both are covered in
[Maximize placement and half tables](/docs/layout/maximize-and-half-tables); the
pipeline order is in [How placement works](/docs/layout/how-placement-works) and
every Site-tab input above is in [Site parameters](/docs/inputs/site).

On a CAD drawing or an image continued as layout only, give a latitude or set
tilt and pitch by hand before generating — see the entry above.

</Accordion>
<Accordion title="Tables are missing in a band right across the site">

A straight strip with no tables in it, running the full width or length of the
plot, is a **transmission line corridor**. A line feature in the boundary file is
given a setback buffer on each side, so the corridor is twice the setback — the
default 15.0 m per side is a 30 m band. The setback is yours to set, from 0 to
500 m per side: raise it for a higher-voltage line — the field's own guidance
suggests 30 m per side for a 400 kV line — or lower it if the corridor is
over-wide, then regenerate. If the band is not straight, or does not run edge to
edge, it is a water body, a canal or an obstruction instead.

</Accordion>
<Accordion title="The table columns do not line up across the plant">

**Maximize placement** is on. It positions each row independently so the row hugs
the exact boundary edge, fitting extra tables against diagonal and curved fences.
The cost is that table columns are **not** vertically aligned across rows, and
the computation takes longer on a large site. If aligned columns matter more than
the extra tables — for a construction drawing, or a cleaning line that must run
straight — untick it and regenerate.

</Accordion>
<Accordion title="There is empty ground on part of the plant">

The likeliest cause is a **capacity cap**. Sizing the plant from a target AC
capacity offers to regenerate the layout trimmed to the target DC capacity, and
once that is accepted the layout stops at the target — so ground that could carry
tables is deliberately left clear. Check whether the run came from **Simulation
with AC Capacity** in the **Studies** card on the **Tools** tab, then raise the
target AC capacity or the DC/AC ratio and run it again; the default overload
limit is 1.5 for string inverters and 1.4 for central inverters. See
[Sizing from an AC capacity](/docs/simulation/ac-capacity).

If no cap was applied, switch **Contour / terrain** on in the **Layers ▾**
popover and check the empty ground is not excluded steep ground, a depression,
or under an obstruction.

</Accordion>
<Accordion title="The number of control rooms is not capacity ÷ ICR Block, or changed after the run">

The count is worked out **per separate piece of land**. Tables separated from
the rest by a gap of more than 300 m form a piece of their own, and each piece
gets its capacity ÷ **ICR Block** (default 18.000 MWp), rounded up, in control
rooms, however small it is. So a site in several distant pieces can need more
rooms than the plant total ÷ **ICR Block** — each small far-off piece gets its
own.

The count then follows the capacity actually left. Placing the rooms clears the
tables under their footprints, so the count is **re-checked** against what
remains and can come out higher or lower than it started. On fixed tilt it is
checked again after the building-shadow keep-clear, and that step can only
lower it. Road width, obstructions and the shadow window can therefore all
change the count. Nothing is wrong. If you want a particular number of rooms,
set **ICR Block** to the capacity you want each one to serve —
[Control rooms](/docs/layout/icr) covers how the blocks are formed and how to
move a building by hand.

</Accordion>
<Accordion title="The Summary shows design warnings">

A **design warnings** banner above the Summary sheet, and a **Design warnings**
chip at the head of the plant chips, mean the layout is complete but something
in it falls outside the design rules: a control room carrying more inverters
than its rating, a control room the plot needs but could not fit, an AC trench
the router could not keep inside the plant or away from a table, an inverter
feeder over one cable run or over its voltage-drop limit, the plant's average
LV voltage drop over budget, or a DC trunk too long. Each line of the banner
names the plot and the finding.

A warning **never blocks anything** — you can still export — but it travels
with the design: the PDF summary page and the Word report's **Design Summary**
carry a **DESIGN WARNINGS** block, and the bill of materials carries a
`Check:` remark on the row it qualifies. The cable checks need **Calculate
cables** on; with cables off they say nothing. Fix the cause and generate
again; the banner clears when the design is clean. What each check means and
how to clear it are on [Design warnings](/docs/reference/design-warnings).

</Accordion>
</Accordions>

## Out-of-date results

<Accordions>
<Accordion title="Exports are greyed out, or the Export menu says Regenerate first">

An input has changed since the layout was generated, so the results on screen
belong to the last run rather than to the inputs in front of you. The **Export
▾** menu opens with the amber row ***Inputs changed since the last run.***
*Regenerate first.* and every item under it disabled, **Export Image (PNG)**
included. The exports outside the menu — the BOM and SLD exports, the pile
Excel, the TMY CSV, an ICR block window's **PDF…** — are refused with the
status-bar message *"Inputs changed since the last run. Regenerate first."*
**Calculate Energy** is refused too.

Other signs: the button reads **Regenerate Layout** with the change named or
counted under it, the changed field is amber, its tab carries an amber dot, and
the plot is dimmed under an **Out of date:** note. Click the **Show … changes**
link on that note to see each change with its value at the last run; clicking
one takes you to the field. Either change the value back — the layout is current again — or click
**Regenerate Layout**. Saving the project is allowed while out of date. See
[Out-of-date results](/docs/workspace/out-of-date-results).

</Accordion>
<Accordion title="The energy result was cleared after I regenerated">

Every Generate that replaces a layout clears its energy result, even when no
input changed, because the energy belonged to the layout that was replaced. The
Energy view then reads **Layout regenerated** and the status line adds *"| the
energy result was cleared: calculate energy again"*. Click **Calculate
Energy** on the Yield tab, or **Calculate energy** on the Energy view, for the
new layout — and calculate energy after your last Generate.

Changing a loss on the Yield tab also makes the layout out of date, so
**Calculate Energy** is refused until you regenerate, and the regenerate then
clears the old result. See [How yield is calculated](/docs/energy/overview).

</Accordion>
</Accordions>

## Cables

<Accordions>
<Accordion title="No cable lengths are reported">

Cable calculation is **off** by default. Inverter and monitoring-box counts are
still computed, but every CABLES row in the Summary view reads `—` and the cable
rows of the **Layers ▾** popover stay disabled. Tick **Calculate cables** in the
**Cables** card on the **Electrical** tab and regenerate. The application warns
you first that the calculation can take a long time on a large or complex layout
and recommends leaving it off until the layout is settled — which is the right
order to work in. See [Cables](/docs/inputs/cables).

</Accordion>
<Accordion title="Medium-voltage cables are missing">

Medium-voltage cables run from each inverter control room to the **main control
room**, so there is nothing to route until the main control room exists, and it is
not placed automatically. On the **Tools** tab, click **Place MCR**, then click a
position inside the boundary.

Placing it does not route anything by itself. The card's hint reads *"MCR placed.
Enable 'Cable Calc' and regenerate layout to route MV cables."* — the **MV cables
(ICR→MCR)** row of the Layers popover has nothing to draw and the Summary's **MV
cable (m)** reads `—` until you click **Generate Layout** again with **Calculate
cables** on. The status line then adds *"| MV cable: n m"*. On a multi-plot
site, placing the main control room also drops a unit substation in every other
plot, and each plot's control rooms route to theirs. See
[Site equipment](/docs/layout/site-equipment).

</Accordion>
<Accordion title="The trench lengths did not change after I drew an obstruction">

Drawing an obstruction on the **Tools** tab clears the tables under it and
re-places the inverters, and with **Calculate cables** on it re-routes the
cables, so **String DC cable (m)** and **AC cable to ICR (m)** are re-measured.
The **DC trench** and **AC trench** rows keep their previous figures, because
trench totals are worked out only at the end of a full cable run — a
**Generate**, or leaving Sketch Mode after a change. **Undo Last**, **Clear
All** and dragging a control room behave the same way, and none of them
rebuilds the bill of materials. Generate again after drawing obstructions
before you quote a trench length.

</Accordion>
<Accordion title="A cable route is much longer than the direct line">

Routing is right-angled: feeder routes are made of horizontal and vertical
segments only, with no diagonals. A set of patterns is tried in turn, ending in
a best-effort path that always returns something connected, so a blocked
corridor produces a long route, not no route. DC runs are kept inside the
usable area, off the perimeter road; AC feeders and DC trunks are kept inside
the plant boundary where the router can manage it, and a run it cannot bring
inside keeps its route and is reported as the design warning **Trench outside
plant**.

Look at what is blocking the direct line — an obstruction, a water body, a
corridor. If the blockage is not real, remove it from the input and regenerate;
otherwise draw the trench you intend to build by hand. See
[Cable routing](/docs/layout/cables).

On a plot of more than 30 000 tables and more than 200 inverters or monitoring
boxes, the DC cabling is drawn for a sample of
clusters and the DC trench is scaled from it to every table; the bill of
materials and the reports mark that figure *"(est.)"*. Every inverter's own
feeder is still routed in full.

</Accordion>
<Accordion title="My hand-drawn trenches disappeared after Generate">

A trench drawn in Sketch Mode replaces every automatic run of its type in the
plot, and it survives leaving Sketch Mode — but **Generate Layout** lays the
plant out and routes every cable afresh, so drawn trenches do not survive it.
Deleting an automatic run with **✂ Del Trench** lasts only inside the Sketch
session: with **Calculate cables** on, leaving Sketch Mode re-routes the cables
and the run comes back.

Draw trenches after your last Generate, and do not rely on deleting automatic
runs. The trench tools are in [Sketch Mode](/docs/editing/sketch-mode).

</Accordion>
</Accordions>

## Energy

<Accordions>
<Accordion title="There are no energy figures">

Three causes. **Energy has not been calculated** — generating a layout does not
calculate it, so click **Calculate Energy** on the **Yield** tab, or
**Calculate energy** on the **Energy** view, once the layout exists; a Generate
also clears an earlier result. **The layout is out of date** — **Calculate
Energy** is refused with *"Regenerate the layout first: inputs changed since
the last run."* until you regenerate. **The site has no known location** — a
CAD drawing or an image continued as layout only; see the entry under loading a
boundary file. See [Weather data](/docs/energy/weather).

</Accordion>
<Accordion title="The irradiance came from a service I did not expect">

With the automatic weather source selected, irradiance is fetched in a fixed order
of preference. The first service returns in-plane irradiance directly for your
position and tilt; when it has no data for the site a second service is used
instead — monthly irradiance climatology with a simple tilt correction — and the
source line under the irradiance fields on the Yield tab names whichever service
was actually used. If neither returns data, the figures stay at zero and the
source is reported as unavailable.

Read that line before you trust a yield number. If the fallback was used and you
need something better, select **Hourly GHI file (CSV)** and supply your own measured
or purchased year.

</Accordion>
<Accordion title="The time-series export is unavailable">

**Export TMY data CSV** writes a full year of irradiance and energy at a chosen
interval, so it needs an **hourly** series to write from, and a monthly figure
cannot be expanded into one. Either load an hourly file, or use the automatic
source with an hourly fetch, then calculate energy and export again. It is also
refused while the layout is out of date. See
[The energy time series](/docs/energy/timeseries).

</Accordion>
<Accordion title="The temperature loss never changes">

With no module file loaded, the temperature loss stays at its default of 6.0 % — an
assumption you can edit, not a calculation. The model needs the module's power
temperature coefficient, and that comes from the module file. Load a `.PAN` file
on the **Array** tab and the loss is recomputed from the mounting type, the wind
speed, the ambient temperature and the module's own coefficient, with the computed
module temperature shown beside the row. See
[Temperature losses](/docs/energy/temperature).

</Accordion>
</Accordions>

## Terrain

<Accordions>
<Accordion title="Terrain is on but nothing was excluded">

A terrain failure is **non-fatal by design**: if the elevation data cannot be
fetched or a contour file cannot be read, the layout proceeds without terrain
exclusion rather than stopping, so a successful run does not prove terrain was
applied. Check, in order:

1. **The excluded area was reported.** Excluded ground is reported in acres —
   the **Contour / terrain** row of the **Layers ▾** popover carries an *RL:*
   readout with the excluded area — so nothing reported means no exclusion
   happened.
2. **The Contour / terrain layer shows contours** — green for low ground through
   blue to red for high ground. No contours means no elevation data.
3. **The connection.** With no contour file supplied, the elevation model is
   fetched from public satellite data, which needs an internet connection — and
   a known site location, so a site continued as layout only never fetches it.
4. **The contour file's coordinates.** A contour DXF must be drawn in the
   boundary file's coordinates: UTM for a Google Earth file or a drawing
   located by its own coordinates, the drawing's own coordinates for a CAD
   boundary placed by latitude and longitude or continued as layout only. A
   file in any other system will not line up. A site continued as layout only
   takes a contour DXF only, not a CSV.
5. **The limits are tight enough to bite.** Ground has to exceed the north–south
   or east–west slope limit to be excluded, and gentle ground never does. See
   [Topography](/docs/inputs/topography).

</Accordion>
</Accordions>

## Studies

<Accordions>
<Accordion title="Earthing Design says Generate first">

**Tools ▸ Earthing Design…** opens at any time, but the earthing calculation
works on a generated layout: with none it shows **Generate first** — *"Generate
a layout first, then open Earthing Design."* The **⚡ Earthing Design** button in
the **Studies** card on the Tools tab is greyed out for the same reason. Click
**Generate Layout**, then open it again. Plots of water, and plots with no
tables, are left out of the calculation.

After a Generate or a layout edit, close the Earthing Design window and open
it again so that it works on the current layout. See
[Earthing design](/docs/simulation/earthing).

</Accordion>
</Accordions>

## Exports

<Accordions>
<Accordion title="The report has no single-line diagram">

The **Single Line Diagram** annexure of the Word report carries your diagram —
or the automatic one when you have none — and it is **skipped silently** if
the drawing errors — so a diagram problem never
blocks the rest of the report. Open the **SLD** view and check the diagram is
actually there. If it is and the annexure is still absent, something in the
drawing is at fault: remove the most recently added content — an imported
background, or an imported symbol — and export again from **Export ▾ Export
Detailed Project Report**. See [The project report](/docs/exports/project-report).

</Accordion>
<Accordion title="The report has no energy section">

The **Energy Yield & Loss Analysis** section and the energy drawings are present
only when an energy calculation has been run for the current layout; nothing else
gates them. A Generate clears the energy result, so click **Calculate Energy** on
the Yield tab after your last Generate, then export again. Two energy figures are
written when monthly data is available, otherwise one.

</Accordion>
<Accordion title="There is no PDF of the report in the Export menu">

The report is a Word document — **Export Detailed Project Report**. The menu
carries two PDFs. **Export ICR-Block PDF** — the plant and one sheet per ICR
block — is there once inverters are placed. **Export PDF (with Piles)**, the
report with the pile drawing, appears only while a pile pattern exists and the
pile overlay is on: click **Piles: OFF** in the Layout tools, define a pattern
and apply it. See [Piles](/docs/editing/piles).

</Accordion>
<Accordion title="A layer is missing from the CAD drawing">

Three groups of layers are conditional. The **cable layers** are written only
when cable calculation was on for the run; the **arrester layer** only when
arresters were placed; and the **pile layer** only when a pile pattern exists
**and** the view header reads **Piles: ON** at export — a pattern alone is not
enough. Put the setting right, regenerate if it is a run setting, and export
again. The full layer list is in [The CAD drawing export](/docs/exports/dxf).

</Accordion>
<Accordion title="The diagram exported as a DXF, not a DWG">

Expect a `.dxf` despite the button's name. The diagram export writes a `.dxf`,
which every CAD program opens, and turns it into a `.dwg` only when the free
ODA File Converter is installed on the machine — the application does not
include it. If you need a `.dwg`, open the `.dxf` in your CAD program and save
it as DWG there — the content is the same either way. See
[Exporting the diagram](/docs/sld/export).

</Accordion>
</Accordions>

## Projects

<Accordions>
<Accordion title="A project file will not open">

A project file is a tamper-evident container. It carries a signature over its own
contents, and a file whose signature does not match what it contains is **reported
as an error rather than loaded** — the application will not open a session it
cannot verify. Likely causes, most common first: the file was truncated in transit,
cut short by a mail gateway or copied from a share while it was still being
written; it was edited, or opened and re-saved by another program; or it is not a
project file from this application.

Fetch the file again from wherever it came from, ideally inside a compressed archive
so nothing rewrites it on the way. If no intact copy exists, the session has to be
rebuilt from the boundary file and your inputs.

</Accordion>
<Accordion title="A reopened project opens out of date">

A project remembers the inputs its layout was generated from, and opens out of
date when they do not match. Two causes. **It was saved out of date** — the
state travels with the file. **An input file is missing or has changed** — the
module, inverter, weather or contour file is missing from the saved path, or
its content differs. The list of changes then reads *"not found at \<path\>"*
for a missing file, and the file's row reads *"Not found: \<name\>"*; the path
is kept for the next save.

Put the file back at its path — the layout is current again once the content
matches — or load it again from its new location and regenerate. A project that matches reads *"Opened \<name\> · the layout matches
its inputs"* in the status bar.

Every input is saved. What a project does not keep is the **Earthing Design**
window's inputs, the **Robotic Module Cleaning** window's answers (its fleet
result is kept), the AC-capacity window's **ICR block AC**, and view settings
such as the Layers toggles and **Piles: ON**. See
[Saving and reopening projects](/docs/projects).

</Accordion>
</Accordions>

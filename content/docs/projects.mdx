---
title: Saving and reopening projects
description: The .slp project file keeps a working session — every input, the layout, hand edits, diagram, BOM edits and issued revisions — and reopens ready to work on, or says what changed.
---

A project file keeps a working session, so you can stop mid-design and come
back to it. It uses the extension `.slp`, for Solar Layout Project, and it is
written and read only by the application itself.

This is separate from exporting. The deliverables package, the BOM files and the
earthing drawings are for the people who build the plant. The project file is for you: it is the only thing
that lets you resume work rather than repeat it.

## What a project file holds

Almost everything. **Every input on the five stage tabs is saved**, and so is
everything the application worked out from them.

| Kept in the file | Meaning |
| --- | --- |
| The boundary and its location | The boundary file's path, the choice made in the **Site reference** window for a CAD drawing or an image, and the image scale |
| The input files | The paths of the module, inverter, hourly weather and contour files — kept even when a file has since gone missing |
| The Array inputs | Module size and wattage, bifacial and its factor; table orientation, modules per row, rows per table and the gaps; the tilt and pitch override ticks and values; every tracker field; **Maximize placement** and half tables |
| The Site inputs | Road width, the **Place Lightning Arresters** tick and radius, **ICR Block**, the **Line corridor** and **Area setback** with the rows for each line and area; everything in **Structures & Shadow (keep-clear)**; everything in **Topography (slope-aware exclusion)** |
| The Electrical inputs | Max strings per inverter or SMB, the DC harness, string fuses, communication and weather stations, max SMBs per central inverter, the **Calculate cables** tick, the three cable allowances, the laying choices, the DC trunk conductor, and the rules on the **ACCB & Transformer** card |
| The Yield inputs | The weather source, GHI and GTI, every loss, the automatic shading tick and ground clearance, the site conditions, albedo, degradation, lifetime, uncertainty and the three exceedance probabilities |
| The layout | The placed tables or tracker units, control rooms, inverters or monitoring boxes, arresters, the routed cables, and the electrical grouping into ACCBs and transformers |
| Your hand edits | What you did in Sketch Mode — moved and added units, hand-drawn and deleted cable trenches, annotations, dimensions and text — plus drawn obstructions, the main control room, unit substations, handover points and placed objects |
| The pile patterns | The full and half patterns and the radius |
| The results | The terrain result, the energy result, and the robotic-cleaning fleet result, which brings the window's answers back with it |
| The studies' inputs | The **Simulation with AC Capacity** window's inputs, **ICR block AC** included, and the **Earthing Design** inputs you changed |
| The single-line diagram | The symbols, wires and text on the drawing sheet, its paper and its traced background |
| The bill of materials | The profile in use and your edits to it. The quantities are not saved: they are counted again when the project opens |
| The deliverables | The project details, this project's copy of the company, check acceptances, the output folder, and every issued revision with its design kept |
| **Advanced settings** | Each setting you changed from its default |
| The grid connection | **On this site** or **By others** |
| The run record | Which inputs produced the layout, so a reopened project knows whether it is still current |

A saved layout is kept exactly as it was, hand edits included. A later
**Generate Layout** builds a new one: it re-places every table and re-routes
the cables, keeping your obstructions, control room, objects, annotations and drawn
trenches but not hand-placed tables. See
[Sketch Mode](/docs/editing/sketch-mode#what-generate-layout-does-to-your-edits).

### What it does not keep

- Anything from **Robot count from DXF…**, which never touches the project.
- The last values used in **Shadow View**, the energy chart and the auto grid, and
  the object size last used in **Place Object**. These last the session.
- The SLD's undo history, its **Diagram** or **Sheet** choice and its zoom.
- View settings: the **Layers ▾** switches, **Satellite**, **Wireframe**,
  **Piles: ON** / **Piles: OFF** (**Piles** returns off), **Plant** or **By block**
  on the Summary (it opens on **By block**), and **Hide passed** on the Checks view.

### What sits outside the project

Three folders in your Windows user folder belong to this computer, not to a project:
`SolarLayout_Company` (your [companies](/docs/exports/company)),
`SolarLayout_BOM_Profiles` ([BOM profiles](/docs/bom/profiles)) and
`SolarLayout_Symbols` (your own SLD symbols). A project keeps its own copy of the
company and the BOM profile it uses, so it opens elsewhere without them.

## The File menu

| Item | What it does |
| --- | --- |
| **New Project** (**Ctrl+Shift+N**) | Opens a fresh window at the defaults, in the same design as this one |
| **Move to String / Central Window…** (**Ctrl+N**) | Opens the New design window and launches a second window for the design you choose; this one stays open |
| **Save Project…** (**Ctrl+S**) | Writes the current session to a `.slp` file |
| **Open Project…** (**Ctrl+O**) | Reads a `.slp` file back |
| **Open Sample Site** | Loads the bundled sample site — one boundary with a pond, a transmission line and an obstruction |
| **Company…** | Your company's name, logo and drawing-number pattern for the title blocks. See [Company](/docs/exports/company) |
| **Advanced settings…** | The rare design inputs, kept per project; it reads *"Advanced settings… (N changed)"* when any is changed. See [Advanced settings](/docs/workspace/advanced-settings) |
| **Exit** (**Ctrl+Q**) | Closes the application |

## Saving a project

Use **Save project**, beside **Export ▾** at the right of the view tabs in
every view, or **File ▸ Save Project…**. Choose a folder and a name; the file
type row reads *PV Layout Project (\*.slp)*, and the status bar confirms with
*"Project saved (full): …"*. If the file cannot be written, a **Save Failed**
box opens with *"Could not save project file:"* and the reason in words, such as
*"Permission denied"*. A failed save leaves the old file whole. If the file is held
by another program the box reads *"The project file could not be replaced: it may be
open in another program. The copy on disk is unchanged. Close that program and save
again."*

Saving needs no active access and is allowed while the layout is out of date. The
state is saved with it: a project saved out of date opens out of date. While a
layout, cable, weather or edit run is going, the save waits: the status bar reads
*"Saving \<name\> when the layout finishes…"*, and the file is written when the run
ends.

Save after anything you would not want to redo: a run whose inputs took a while to
settle, a set of hand edits, a diagram you have laid out, or changes to the materials
list.

### Closing with unsaved changes

Changes to the project details, the company, the output folder, the grid connection,
the earthing inputs, Advanced settings, BOM settings and check acceptances mark the
project as changed, with a `*` in the window title. Closing such a window asks **Save
changes?** with **Save**, **Discard** and **Cancel**. Save the project yourself after a
Generate, input edits, Sketch edits and BOM line edits.

## Reopening a project

**File ▸ Open Project…**, then pick the `.slp` file. The session is restored
and you carry on from where you stopped. An open Earthing Design window and the
Export deliverables window close first, and the SLD editor ends. A project saved in a different design asks first, under the title
**Design Mode Mismatch**; a project whose inputs could not all be restored
opens with **Partial Restore** — *"Input settings restored with warnings:"*. A saved
section the application cannot use says so in a box of its own, for example **Advanced
settings had problems**.

A project with no company takes this computer's default company, if you have set one;
a project with a company keeps its own copy.

The status bar says what state the project opened in:

| Case | Status bar |
| --- | --- |
| A layout that matches its inputs | *"Opened \<name\> · the layout matches its inputs"* |
| A layout that is out of date — it was saved that way, or an input file is missing or has changed | The out-of-date line, *"Out of date: … Regenerate the layout to update results and exports."* |
| A project saved by an earlier release of the application | *"Opened \<name\>, saved by an earlier version: 1 input was restored from its saved layout"* (or *"… N inputs were restored …"*) |
| A project with no layout | *"Project loaded: \<name\>"* |

### Tools ready without a Generate

A project whose layout matches its inputs opens with these ready, without
generating again:

- **Export ▾** offers its items: **Export deliverables…**, the BOM files, the earthing
  layout and the image.
- **Satellite**, **Piles** and the **ICR blocks** layer are available (and off);
  saved piles can be shown.
- The arrester layers are available, and so are the cable layers when the saved run
  had cables calculated.
- On the Tools tab, the obstruction, MCR and object tools work, with **Remove MCR** and
  **Remove Objects**, and so do the **Studies** buttons.
- **Calculate Energy** is available where the site's location is known.
- The Electrical tab shows the saved grouping of inverters into ACCBs and
  transformers.
- The Summary opens on **By block**.

### A project that opens out of date

A project opens out of date when it was saved that way, or when an input it
was generated from differs from what it was. For each missing module, inverter,
weather or contour file, the list of changes reads *"not found at \<path\>"*
and the file's row on its card reads *"Not found: \<name\>"*. The layout is
still shown, greyed, and exports wait until the layout is current again. The path is kept in the project the next time you save.

Opening a project restores exactly the files that project was saved with,
never those of another open window. See
[Out-of-date results](/docs/workspace/out-of-date-results#saving-and-reopening-while-out-of-date).

## Starting fresh

**File ▸ New Project** opens a fresh window at the defaults in the same
design; the current window stays open, so save it first if it is worth keeping
— nothing is written to disk unless you write it.

## Moving to a different design

The mounting and inverter choices belong to the window and cannot be changed
inside it. The **design chip** in the ribbon — reading *Fixed tilt · String
inverter ▾* or the like — and **File ▸ Move to String / Central Window…** both
open the New design window and launch a second, independent window beside this
one. The new window starts empty: it does not inherit the boundary file, the
inputs or the layout. See [Choosing a design mode](/docs/design-modes).

## The file checks itself when it opens

A project file is a single binary container, not a text file. It carries a
checksum computed over its own compressed contents, which is verified before
anything is loaded. A file that has been altered, truncated by a failed copy,
or is not a project file at all fails that check and is reported as an error —
**Open Failed**, *"Could not open project file:"*, with the reason, for example
*"Project file integrity check failed."* — instead of opening.

<Callout type="warn">
Do not edit a `.slp` file by hand, and do not try to produce one from another
tool or a script. Any change to its bytes — including a well-intentioned one —
makes the checksum disagree with the contents, and the application refuses the
file rather than loading part of it.
</Callout>

Two practical consequences:

- **Copy project files whole.** Move them with a normal file copy, and check
  the copy opens before deleting the original. A transfer that stops partway
  leaves a file that does not load.
- **To get the design out of the application, export it.** **Export
  deliverables…** carries the design into formats other tools read: a drawing set as
  PDF and DXF, the design report, Excel schedules and a BOM workbook, and a Google
  Earth file. The DXF is in UTM metres, or in the drawing's own coordinates for a CAD
  or image boundary placed by hand or loaded as layout only. See
  [Exports](/docs/exports/overview).

## Comparing several designs on one site

Every window is its own session, and two or more can be open at once, so
options can be compared side by side as well as as separate project files. A
workable habit:

1. Load the boundary file, set the inputs your design fixes, generate, and save
   as one project per option — a portrait table against a landscape one, a
   derived row pitch against a tighter one you override, arresters on against
   off. **File ▸ New Project** gives each option its own window.
2. Give each file a name that states the variable, not a version number, so the
   comparison survives being read months later.
3. Read the same Summary rows in each — **DC capacity (MWp)**, **Full tables**,
   **ICR blocks** and, once energy has been calculated, **CUF on DC (%)** and the
   probability rows. **Open in window** puts the sheet in a window of its own, for
   example on a second monitor.

Changing the mounting or the inverter topology is the one comparison that
needs the design chip rather than New Project, because those belong to the
window rather than the inputs.

The **Cables** card decides whether the application routes and measures the
cables between the tables, the inverters or string monitoring boxes (SMBs) and the
control rooms, how each class of cable is laid, and what allowances are added to
the DC string-cable total. It is the third card on the **Electrical** tab, after
the inverter card and the **ACCB & Transformer** card (**Transformer** in a
central-inverter design — see
[ACCB and transformers](/docs/inputs/accb-and-transformers)). Routing is off as
shipped, because it is the slow step on a large plant. The equipment is placed
and counted whether or not the cables are traced.

How the runs are routed once the option is on — the patterns, the trenches and
the medium-voltage network — is on [Cable routing](/docs/layout/cables). This
page covers the card.

## The fields

| Field | Default | Range | What it does |
| --- | --- | --- | --- |
| **Calculate cables** | off | — | Routes every run on the next **Generate Layout** and reports the lengths |
| **DC string cable laying** | Buried, in conduit | or Buried directly · Above ground, in conduit on concrete blocks | How the DC string cables are laid |
| **AC cable laying** *(string)* / **DC trunk laying** *(central)* | Buried directly | or Above ground, on concrete blocks | How the AC feeders or the DC trunks are laid |
| **MV cable laying** | Buried directly | or On cable tray | How the medium-voltage cables are laid |
| **Inter-module lead** | 0.00 m/module | 0.00–2.00 m/module | Extra string cable per module for the leads between modules, counted once per string. Fixed-tilt tables only |
| **String return run along table** | off | — | Tick for daisy-chain wiring: adds one conductor's run back along the table per string. Fixed-tilt tables only |
| **DC cable slack** | 10.0 % | 0.0–30.0 % | Slack and wastage added to the DC string-cable total, trackers included |
| **DC trunk conductor** *(central)* | Aluminium | or Copper | The metal of the SMB-to-central-inverter cable |
| **Voltage-drop limits** | *all at defaults* | — | **Advanced…** opens the limits the cables are sized to |

The tick, the laying choices, the conductor and the allowances are saved in the
project file and come back when it is reopened. They are also inputs to the run:
change any of them after generating and the layout is marked out of date until
you generate again. See
[Out-of-date results](/docs/workspace/out-of-date-results).

## Calculate cables

**Off by default.** With it off, the layout is generated, the inverters or
monitoring boxes are placed and counted, and no cable is routed. With it on,
the application traces every run on the next **Generate Layout** and reports
its length.

What gets traced depends on the design, because the conversion happens in a
different place:

<Tabs items={["String inverter", "Central inverter"]}>
<Tab value="String inverter">

| Run | From | To |
| --- | --- | --- |
| String DC cable | Each table (MMS) | Its string inverter |
| AC cable | Each string inverter | Its ICR |

The inverter converts in the field, so the run into the control room is AC.
The totals appear on the **String DC cable (m)** and **AC cable to ICR (m)**
rows of the Summary view.

</Tab>
<Tab value="Central inverter">

<Screenshot id="cables-group-central" maxWidth={420} />

| Run | From | To |
| --- | --- | --- |
| String DC cable | Each table (MMS) | Its string monitoring box |
| DC cable | Each string monitoring box | The central inverter, counted twice for the positive and negative conductors |

There is no AC leg, because the central inverter sits inside the ICR building.
The totals appear on the **String DC cable (m)** and **DC cable to central
inverter (m)** rows of the Summary view.

</Tab>
</Tabs>

Medium-voltage runs from the control rooms to the main control room are routed
in both designs, once a main control room has been placed and the layout
generated again with this option on. With the grid connection by others they run
to the [handover point](/docs/layout/grid-connection) instead, when there is one.

### The performance notice

Ticking the box raises **Cable Calculation — Performance Notice** before
anything is enabled. It reads: *Cable calculation can take a long time on large
or complex layouts.* — *It is recommended to generate the plant layout first
without cable calculation, review the result, and then enable cable calculation
for the final run. Do you want to enable cable calculation now?*

<Screenshot id="cable-calc-notice" />

| Button | What it does |
| --- | --- |
| **Enable Now** | Leaves the box ticked. Cables are routed on the next Generate Layout |
| **Not Now (Recommended)** | The default. Unticks the box again |

Opening a saved project that had the option on does not raise the notice.

<Screenshot id="cables-group-on" maxWidth={420} />

<Callout type="warn">
Take the recommendation on a plant you have not laid out before. Cable routing
is the slow step on a large plant, and it is the step whose result you are
least likely to keep: change the table configuration, the perimeter road, the
ICR block or the strings per inverter, and every run is traced again from
scratch.
</Callout>

### What you still get with cables off

- **The inverter and monitoring box counts are computed anyway.** So are their
  loads, the central inverter count, and everything downstream that depends
  on them — the AC capacity, the DC / AC ratio, the single-line diagram and the
  bill of materials.
- **The cable rows of the Summary view read *needs Calculate cables*,** as a link
  to this card.
- **The cable rows of the Layers popover stay disabled.**
- **The design check C-06 Cables computed stays open,** and the checks that read
  the cables say what they need. See
  [Design checks](/docs/reference/design-checks).

One more run with the box ticked fills in the cable numbers.

## How each cable class is laid

The three laying fields decide what each class needs beside the cable, and
whether it counts as trench. A plot records the laying it was routed with, so
changing a field alone changes nothing until the next **Generate Layout**.

| Class | Option | What it means |
| --- | --- | --- |
| DC string | **Buried, in conduit** | Each DC route's cables in one 40 mm HDPE conduit, in a trench |
| | **Buried directly** | In a trench, no conduit |
| | **Above ground, in conduit on concrete blocks** | In the conduit, on concrete blocks; no trench |
| AC feeder or DC trunk | **Buried directly** | In a trench |
| | **Above ground, on concrete blocks** | On concrete blocks, clamped; no trench |
| MV | **Buried directly** | In a trench |
| | **On cable tray** | No trench; the BOM measures the tray along the MV route |

Only buried classes count as trench. The Summary view's trench row for a class laid
above ground reads *laid above ground*, and for MV on a tray *on cable tray*. The
bill of materials follows: conduit and its fittings, concrete blocks, clamps and
tray appear with the laying that needs them. See
[Bill of materials](/docs/bom/overview).

## The three DC allowances

The routed length of a string cable is the distance from the table to the
inverter or monitoring box. Three further figures turn that into a quantity you
can order against, and they are added to the DC string-cable total only.

### Inter-module lead

**Inter-module lead** is extra string cable allowed **per module** for the
leads that join one module to the next, counted **once per string**. It ships
at **0.00 m per module**, because the module supplier normally provides these
leads with the modules. Enter a figure only when your procurement buys that
cable separately. It applies to **fixed-tilt tables only**.

### String return run along table

How much string cable a table needs depends on how its strings are wired.

| Wiring | The string's two leads | Setting |
| --- | --- | --- |
| **Leapfrog** | Exit at the same end of the table | Leave **String return run along table** unticked — the default |
| **Daisy-chain** | End at opposite ends of the table, so one conductor must run back along the table to exit beside the other | Tick **String return run along table**, and that run back along the table is added per string |

It applies to **fixed-tilt tables only**.

### DC cable slack

**DC cable slack** is the slack and wastage added to the DC string-cable total,
as a percentage. It ships at 10 %, the bill-of-quantity convention. Unlike the
other two allowances it applies to every design, tracker plants included.

## DC trunk conductor

Central-inverter design only. The trunk from each SMB to its central inverter is
sized in the metal you choose, by voltage drop and current-carrying capacity, as
two single-core conductors. On one sample plant the same trunk came out at 150 mm²
in aluminium and 120 mm² in copper. The lugs in the bill of materials follow the
metal: **DC cable lug, bimetallic** for aluminium, **Cable lug, copper** for copper.
The string cables are copper either way.

## Voltage-drop limits

The limits the cables are sized to are
[Advanced settings](/docs/workspace/advanced-settings), not fields on this card. The
row shows *all at defaults* or how many are changed, and **Advanced…** opens them.

| Setting | Default | What it limits |
| --- | --- | --- |
| **DC string voltage drop** | 1.5 % | The DC string cables; design check E-08 |
| **LV feeder drop limit** | 2.5 % | Each inverter-to-ACCB feeder; design check E-02 |
| **MV voltage drop** | 2.0 % | The MV cables; design check E-02 |

Each inverter-to-ACCB feeder is one run of the plant's size A or size B. Size A is
the smallest standard size whose derated current-carrying capacity carries the
feeder's current; size B is the next one up. A feeder takes A unless its drop
exceeds the limit, and there is never a third size or a second run. A feeder
neither can serve is flagged in the [schedules workbook](/docs/exports/schedules-and-kmz)
and the checks. The current comes from the inverter file, or from the maximum
strings × the string's power without one. The MV sizing uses the **MV voltage** on
the [ACCB & Transformer](/docs/inputs/accb-and-transformers) card.

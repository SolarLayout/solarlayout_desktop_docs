---
title: Updates and reinstalling
description: How Microsoft Store updates arrive, how to check for one by hand, why your access survives them, and how to reinstall or remove the application.
---

Updates arrive through the Microsoft Store. Microsoft delivers them, so there
is nothing to download, no installer to run, and no patch to apply by hand. In
normal use an update installs itself and the next launch is the new version.

Access to generate a layout is not stored as a file the application keeps. It
belongs to your account and is checked against SolarLayout's server by this
device's Device ID, so replacing the application — an update or a full reinstall — does not
disturb it and an update never asks you to activate again.

## How updates arrive

Windows checks the Store for updates on its own schedule and installs them in
the background. Two things follow from that:

- You may be updated without having asked. That is the intended behaviour of a
  Store application, and it is why the Store is the route these pages
  document.
- An update may wait until the application is closed. Close it if an update
  appears to be stuck.

A copy that did not come from the Store receives no Store updates. The
download page,
[solarlayout.app/downloads/solarlayout](https://solarlayout.app/downloads/solarlayout),
always carries the current version.

## Check for an update by hand

Worth doing if you have been told a fix is out, or if the application has been
open for weeks.

<Steps>

<Step>
### Open the Microsoft Store

Press Start, type *Microsoft Store*, and open it.
</Step>

<Step>
### Open the Library

It is in the left-hand navigation. The Library lists the applications installed
on this machine and any updates waiting for them.
</Step>

<Step>
### Click Get updates

The Store checks every installed application at once and downloads whatever is
pending. If SolarLayout Desktop is already current it is not listed as needing
anything.
</Step>

<Step>
### Close the application before the update installs

If the application is open, close it and let the Store finish. Save your work
first — an update does not preserve an unsaved session.
</Step>

</Steps>

## Which version you have

**The application shows its version at the right of the status bar at the
bottom of the main window** — that is the quickest place to check.
The **Help** menu carries two items — **How to Use This Tool** and
**License / Subscription…** — and there is no About window, so the status bar
is the one place in the application the version is named.

The Store's **Library** listing also shows it, and is the place to check
whether an update is waiting.

[Release notes](/docs/releases) lists what changed between versions.

## Access is checked online, not stored in a file

There is no local licence file to lose, back up or move. Access belongs to
your account, and this device is identified by its Device ID — the Windows
registry MachineGuid, the same value shown under
**Settings ▸ System ▸ About ▸ Device ID** — and checked online against
SolarLayout's server. Updating or reinstalling the application changes
neither that identifier nor the server-side record it is checked against, so
a launch after either one shows the same status as before.

The access chip in the ribbon always shows this at a glance —
**● Active — until \<date>** when active, **● Access expired** or **● Access
revoked** with a **Contact Us** button, or **● Access status unavailable** —
and with no access at all the chip gives way to a gold **Get Free Access**
button, so checking status never requires opening a window.

Help ▸ **License / Subscription…** opens the window that shows it in full: a
headline reading **✓ Active — until \<date>**, **Start your free trial**,
**Access expired**, **Access revoked**, or — right after clicking **Get Free
Access** — **⏳ Waiting for activation** — with your Device ID and its **Copy**
button folded behind **Having trouble?**.

If the application cannot reach the server, a good check made earlier is
cached and it keeps working for a three-day offline grace window, the chip
reading *(offline)* meanwhile.

If a launch after an update or reinstall shows no access, the Device ID has
not changed and neither has the server record — see
[Licence problems](/docs/licence/troubleshooting).

<Callout type="info">
Only **Generate Layout** and the exports need this device's access to be
active. Reading and changing inputs, opening a project, and the SLD and BOM
views work regardless of status.
</Callout>

## Reinstalling

Reinstalling is worth trying when the application will not start at all, or
starts and misbehaves in a way that survives a restart. It is not a fix for a
licence problem — the licence is not part of the installation.

<Steps>

<Step>
### Remove the application

Uninstall it the way you remove any Store application: from its entry in the
Start menu, or from the installed-applications list in Windows Settings.
</Step>

<Step>
### Install it again from the Store

Follow [Install on Windows](/docs/install/windows) — open the Store, search for
the application, check the publisher reads **Rensaar**, and install.
</Step>

<Step>
### Launch it and check access

The **New design** window appears and then the main window, the same as any
launch. Check the access chip in the ribbon, or **Help ▸ License /
Subscription…**, to confirm the status still reads **Active** — it is checked
against the server by Device ID, not restored from anything the previous
installation left behind.
</Step>

</Steps>

## Uninstalling

Removing the application removes the application. It does **not** remove the
work you have done with it:

- **Project files** (`.slp`) sit wherever you saved them and are untouched.
- **Exported reports, drawings, schedules and mapping files** sit wherever you
  exported them and are untouched.

<Callout type="warn">
A different machine has its own Device ID, so it needs activating as a device
of its own. Open Help ▸ **License / Subscription…** on the new machine and use
**Get Free Access** there. Your account covers up to three devices, and a
replaced machine does not free its place. If access has expired or been revoked instead, contact SolarLayout at
[sales@solarlayout.app](mailto:sales@solarlayout.app).
</Callout>

If you are moving to a different machine rather than leaving the product, copy
your project files across first, then activate the new machine as above —
access belongs to your account and each computer is activated on it; nothing
about it travels with your data.
See [How licensing works](/docs/licence/overview).

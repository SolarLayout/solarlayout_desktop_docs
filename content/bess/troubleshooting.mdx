application is doing, why, and which input or state to check.

## Running an analysis

<Accordions>
<Accordion title="A run won't proceed without a generation profile and an activated device">

Two things have to be in place before either **▶  Simulate** or
**⚙  Optimise** will run: this device activated, and — unless the project
type is **4.  Standalone BESS (grid-charged)** — a generation profile
loaded on the **📂 Data** tab.

If access is the gap, open Help ▸ **License…**: the headline reads
something other than **✓  Active**, and the app offers to open this same
window instead of running when either **▶  Simulate** or **⚙  Optimise** is
clicked. See [How access works](/bess/access/overview) and
[Activate this device](/bess/access/activate).

If access is fine, a run still needs a generation profile loaded first,
unless the project type is Standalone BESS. Check the **📂 Data** tab's
status line: it still reads **No file loaded.** until a CSV is loaded and
read successfully, and a Standalone BESS project is the only one that
doesn't need this step, since it builds its own calendar internally. See
[Generation data](/bess/inputs/data).

</Accordion>
<Accordion title="A licence-gated action opens the License window instead of running">

**▶  Simulate**, **⚙  Optimise**, and every export — the PDF report, the
Word report, the plain-text report, the DFR CSV, the time-series CSV, the
dashboard plot, and the Sensitivity Analysis window's own CSV export — all
check this device's access first. When the check doesn't pass, the app
offers to open the License window rather than completing the action.

**Sensitivity Analysis…** itself, once a base case exists, the **🏗  Plant
Layout & SLD** designer, saving or opening a project, and loading a
generation profile are not checked this way — all of those run regardless of
activation status. See How access works for the full split, and
[Access problems](/bess/access/troubleshooting) for what each License
window state means and how to fix it.

</Accordion>
</Accordions>

## Generation data

<Accordions>
<Accordion title="The Data tab's CSV loader is greyed out">

Expected on a **4.  Standalone BESS (grid-charged)** project: there is no
solar or wind generation to read a profile for, so the loader is disabled
and the application builds a full year's 15-minute calendar internally
instead. Choose a different project type on the same tab if the plant is
meant to charge from solar or wind. See Generation data.

</Accordion>
<Accordion title="The wrong values were read from the generation CSV">

The datetime, solar and wind columns are matched by a keyword in the header,
not by position — a datetime-like column needs `time`, `date`, `stamp` or
`datetime` in its name, solar needs `solar`, `pv`, `sun` or `photovoltaic`,
and wind needs `wind`, `wg`, `wtg` or `turbine`. A column that matches none
of those falls back to a synthetic 15-minute index for the datetime column,
or the first and second numeric column for solar and wind — which reads the
wrong column if the file is laid out differently. Rename the headers to
match a keyword and load the file again. See Generation data.

</Accordion>
</Accordions>

## Sensitivity analysis

<Accordions>
<Accordion title="Sensitivity Analysis… won't open, or warns about a base case">

It needs a completed **▶  Simulate** or **⚙  Optimise** result to test
against. Without one, the window warns *"Please run Simulate or Optimise
first to establish a base case."* and doesn't open. Run one of the two
first, then open **Run ▸ Sensitivity Analysis…** again. See
[Sensitivity analysis](/bess/analysis/sensitivity).

</Accordion>
<Accordion title="The Breakeven Solver reports the target isn't bracketed">

The message reads *"Target … not bracketed within [Min, Max]"* — the
lever's search range doesn't reach far enough in either direction to hit
the target metric's value. Widen **Min** or **Max**, which auto-fill to
0.2×–5× the lever's base value and are editable, then solve again. See
Sensitivity analysis.

</Accordion>
</Accordions>

## DFR and penalties

<Accordions>
<Accordion title="A penalty appears even though the year looks fine overall">

The DFR-shortfall penalty is checked separately, every month, at four
granularities — Peak, Off-Peak, Overall monthly and 15-minute — and that
month's actual penalty is the largest of three figures: the Peak penalty
plus the Off-Peak penalty combined, the Overall penalty on its own, or the
15-minute penalty on its own. A shortfall at just one of those granularities
in one month is enough to produce a penalty for that month, even when the
year's totals look fine. Read the **📋 DFR Table** row for that month — it's
shaded red when any of Peak, Off-Peak, Overall or 15-minute DFR missed
target. See [Delivery Fulfilment Ratio (DFR)](/bess/concepts/dfr) and
[OPEX, revenue and penalties](/bess/inputs/opex) for the Penalty Multiplier
and PPA Tariff the formula uses.

</Accordion>
<Accordion title="The Annual DFR target was missed but no extra penalty shows for it">

The Annual DFR target is tracked and compared the same way as the other
four, but on its own it doesn't feed into the penalty formula — only the
Peak-hour, Off-Peak, Overall monthly and 15-minute targets do. See
Delivery Fulfilment Ratio (DFR).

</Accordion>
</Accordions>

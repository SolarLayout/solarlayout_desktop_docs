---
title: Troubleshooting
description: The messages SolarLayout Rooftop shows, by where you meet them, with what each means and what to do.
---

SolarLayout Rooftop says what went wrong where it happens: what happened, what to do, and a button for the first thing
to try. When a run or a file fails after one that worked, the result of before stays on the screen, marked "Showing the
last result". A value outside the usual range is marked with an exclamation mark, never a cross.

The messages below are as the app writes them. A word in angle brackets, such as &lt;file&gt; or &lt;n&gt;, stands
for what the app fills in. If a message keeps coming back, write to SolarLayout as
[Getting help](/docs/rooftop/support) says, with the message word for word and the design's project file.

## Anywhere in the app

<Accordions>
<Accordion title="Energy not computed">
The run that works out the energy failed, and there is no result before it. The result chip at the top bar's right
says so; press it for the cause and **Try again**. On a phone the chip reads "No energy". When the design has no
option, the cause is the reason, with **Open Roof** or **Open Strings** to put it right. See
[The result](/docs/rooftop/steps#the-result).
</Accordion>
<Accordion title="Energy not updated">
A run failed after one that worked. The figures of before stay, dimmed, marked "Showing the last result". Press the
chip, then **Try again**.
</Accordion>
<Accordion title="The server could not be reached. Check your connection, then try again.">
The device could not reach the app's server: the connection is off or dropped. Check the connection, then press
**Try again**. After a change, the cause reads "The server could not be reached after your last change. The result
shown is from before the change."
</Accordion>
<Accordion title="The server did not answer. Try again in a moment. · The app could not finish this step.">
The server answered with a fault or in a form the app cannot read, or the page itself met a fault. Wait a moment,
then press **Try again**. **Details** gives the fault's own words for SolarLayout.
</Accordion>
<Accordion title="&lt;n&gt; to review">
Notes wait: a value outside the usual range, a run or a layout that failed, a chosen option outside its DC/AC target,
or a design the device did not save. Press the result chip, then "&lt;n&gt; to review", for the list. Each note says
where it belongs and has one action, such as **Open Array** or **Try again**. See
[Notes to review](/docs/rooftop/steps#notes-to-review).
</Accordion>
<Accordion title="This browser cannot draw the roof in 3D.">
The browser has no WebGL, so the stage shows a flat plan of the roof, north up, in place of the 3D view, and the view
controls are not shown. In Present the tour goes on over the plan. Open the app in a browser that draws 3D. See
[What the browser needs](/docs/rooftop/getting-started#what-the-browser-needs).
</Accordion>
<Accordion title="The browser stopped drawing the roof in 3D.">
The browser took back its 3D drawing while the design was open. The flat plan of the roof stands in, north up, and
the view controls are not shown.
</Accordion>
<Accordion title="The highest is &lt;max&gt;. · The lowest is &lt;min&gt;. · Enter a number from &lt;min&gt; to &lt;max&gt;.">
A number typed in a field is outside its range, or is not a number. The field is set to the nearest end of its range,
or keeps its value. Type a value inside the range the message gives.
</Accordion>
<Accordion title="This part of the help did not load. Check the connection and try again. · The picture did not load">
A help topic's text, or a picture in it, did not come. Check the connection, then press **Try again**. A clip that
does not load says "The clip did not load. The picture shows the step."
</Accordion>
</Accordions>

## Saving and opening

<Accordions>
<Accordion title="Not saved">
Beside the design's name, a hollow dot with "Not saved" is a design not kept on this device yet: the demo, or a
design before its first change. A change keeps it. The note mark with "Not saved" is a design the device refused to
keep; see the next message. See [Saving](/docs/rooftop/steps#saving).
</Accordion>
<Accordion title="The design could not be saved on this device: &lt;reason&gt;.">
The browser refused to keep the design. In a browser that cannot keep designs, the reason reads "this browser cannot
save designs". Press **Try again** in the note; the next change tries again too. Download the project file from the
project menu to keep the design as a file.
</Accordion>
<Accordion title="the app is open in another tab, which blocks the change">
Another open tab of the app blocks the change to the designs on this device. Close the other tab, then try again.
</Accordion>
<Accordion title="That design is no longer on this device.">
The design was deleted from this device, so it cannot be opened. The design that was open stays open. Open its
project file if you have one. See [Open a project file](/docs/rooftop/projects#open-a-project-file).
</Accordion>
<Accordion title="&lt;reason&gt; The demo is open instead.">
The design remembered as open could not be read from this device, so the demo opened. Open another design from Home.
</Accordion>
<Accordion title="The designs on this device could not be read: &lt;reason&gt;.">
The browser could not read the list of designs it keeps. Open the design you need from its project file.
</Accordion>
<Accordion title="A name is needed">
A design's name cannot be empty. Type a name, up to 200 characters.
</Accordion>
<Accordion title="Choose a project file (.rtd). · The file could not be read. Choose another.">
The file chosen in **Open a project file** does not end in `.rtd`, or the browser could not read it. Choose the
project file the app downloaded, or another copy of it.
</Accordion>
<Accordion title="This file is larger than any project file the app saves. Choose another. · text: String should have at most 5000000 characters">
The file is over about 6 MB, or its text over 5,000,000 characters: more than any project file the app makes. Choose
the `.rtd` file the app downloaded.
</Accordion>
<Accordion title="The file is not a project file (.rtd): &lt;reason&gt;">
The file is not one the app wrote, or it was changed: "it is not JSON", "its JSON is not an object", "it has no
&lt;key&gt;" (for example "it has no roof."), or "it cannot be read as one". Download the project file again from the
device that has the design.
</Accordion>
<Accordion title="The project file cannot be opened: &lt;field&gt;: &lt;reason&gt;">
A value in the file is outside what a design may hold; the field and the reason say which. Download the project file
again from the device that has the design.
</Accordion>
<Accordion title="This project file is format &lt;n&gt;. This version reads formats 1 and 2. Open it with a newer version of the app.">
The file is of a format the app does not read. Write to SolarLayout with the file.
</Accordion>
<Accordion title="The module file &lt;name&gt; (PAN) is not included in this project. Choose it again.">
A project file of format 1 named a file by its place on a disk without carrying it. The same note comes for the
inverter file (OND) and the CSV weather file. Open the project, then choose the file again: the module on the Array
step, the inverter on the Strings step, the weather on Performance.
</Accordion>
</Accordions>

## Find

<Accordions>
<Accordion title="The map is not available">
The satellite map cannot be shown here. The column opens on **Enter the roof by hand**: type the roof's place and its
length and width. See [Enter the roof by hand](/docs/rooftop/find#enter-the-roof-by-hand).
</Accordion>
<Accordion title="This browser cannot draw the map · The imagery does not load">
The browser has no WebGL, which the map needs, or the satellite tiles did not come before any was shown. Try
another browser or check your connection, or enter the roof by hand.
</Accordion>
<Accordion title="Address search is not available. Paste coordinates or a maps link.">
Addresses cannot be searched for. Paste the building's coordinates or a maps link in the field: they are read without
the address search.
</Accordion>
<Accordion title="The address search cannot be reached. Check your connection, then try again.">
The device could not reach the address search. Check the connection, then search again.
</Accordion>
<Accordion title="The address search did not answer. Try again in a moment. · The search failed. Try again.">
The address search answered with a fault, or stopped on one of its own. Wait a moment, then search again.
</Accordion>
<Accordion title="Nothing found for “&lt;words&gt;”. Try a fuller address, or paste coordinates.">
No place matches the words. Add the street, the city or the postcode, or paste the coordinates.
</Accordion>
<Accordion title="Your location is not available. Allow it in the browser, or search for the address.">
The browser refused the location, could not find it, or took longer than 15 s. Allow the location for the app in the
browser's settings, or type the address.
</Accordion>
<Accordion title="These look like coordinates, but they cannot be read.">
The field holds what looks like coordinates in a form the app cannot read. The message ends with two forms that it
reads, "12°54′50.74″N 77°29′31.16″E, or 12.91409, 77.49199". Write them so, latitude first. Other messages name the
fault: only the latitude or only the longitude is there; both are marked N or S; a minus and a letter disagree; the
minutes or the seconds are over 59; a latitude is over 90° or a longitude over 180°.
</Accordion>
<Accordion title="The latitude comes first, and &lt;n&gt; is more than 90°. Did you mean this?">
The first number cannot be a latitude, and the pair fits the other way round. The row **Swapped** offers it: press it,
or Enter.
</Accordion>
<Accordion title="No footprint known here">
**Detect building** found no building outline under the press. Outline the roof by **Corners** or by **Rectangle**
instead. See [Outline the roof](/docs/rooftop/find#outline-the-roof).
</Accordion>
<Accordion title="The outline crosses itself. Move the corners so that no two edges cross.">
Two edges of the outline cross. Drag the corners into their order round the roof, then build again.
</Accordion>
<Accordion title="This outline covers &lt;area&gt; m². SolarLayout designs one roof at a time, up to 30,000 m² (about 3 MWp). For a larger site, outline each building as its own design.">
The roof is larger than the app designs. Outline each building of the site as its own design. The same refusal comes
for a drawing or a project file.
</Accordion>
<Accordion title="The corners of a box must make a rectangle.">
A box obstacle is not a rectangle. Draw the box again, or draw what stands there as a **Building**.
</Accordion>
<Accordion title="The roof could not be built. Try again.">
**Build this roof** failed with no reason from the server. Press it again.
</Accordion>
<Accordion title="&lt;name&gt; is not a KMZ, KML or DXF file. Choose a file with one of these endings.">
**Import a drawing** reads KMZ, KML and DXF files only. Export the drawing in one of them. See
[Import a drawing](/docs/rooftop/find#import-a-drawing).
</Accordion>
<Accordion title="&lt;file&gt; has no polygon to use as the roof. · &lt;file&gt; has no closed polyline to use as the roof.">
The drawing has no closed shape for the roof: a KMZ or KML needs a polygon, a DXF a closed polyline. Close the
roof's outline in the drawing, then choose it again.
</Accordion>
<Accordion title="&lt;file&gt; is not a KML file that can be read · &lt;file&gt; is not a DXF file that can be read · &lt;file&gt; has no KML file inside.">
The file's content cannot be read as a drawing (the reader's own words follow), or a KMZ holds no KML, or one over
20 MB. Export the drawing again, with the roof and its obstacles alone.
</Accordion>
<Accordion title="The app can send a drawing of about 4.7 MB at most. Save this one with only the roof and its obstacles, then choose it again.">
The drawing is too large to send. Save a copy with the roof and its obstacles only, then choose that.
</Accordion>
<Accordion title="&lt;field&gt;: &lt;reason&gt;">
The server refused a value, such as a name over 200 characters. The field and the reason say which. Correct it, then
build or open again.
</Accordion>
</Accordions>

## Roof and Array

<Accordions>
<Accordion title="Layout not updated · Layout not computed">
The modules could not be laid out after a change. The positions of before stay ("Showing the last positions"), or
there are none yet. The reason follows. Press **Try again**.
</Accordion>
<Accordion title="The roof outline encloses no area. Give at least three corners that are not on one line. · The roof outline crosses itself. Give the corners in order around the roof.">
The roof's corners lie on one line, or two edges cross. Edit the outline in Plan on the Roof step: drag the corners
into their order round the roof. See [Outline](/docs/rooftop/roof#outline).
</Accordion>
<Accordion title="The outline cannot cross itself. The roof stays as it was.">
A corner dragged in Plan would make the outline cross itself, or close it to almost no area. The roof keeps its
outline. Drag the corner to another place.
</Accordion>
<Accordion title="The file has no height for these obstacles. The app uses 1.0 m.">
An imported drawing gave no height for some obstacles. Press **Review**: each one shows "Height to review" and "Not in
the file. Enter the real height." Type each height, then press **Next**. See
[Obstacles](/docs/rooftop/roof#obstacles).
</Accordion>
<Accordion title="No module fits on this roof">
"The roof has no room for a module inside the edge margin and clear of shade. Check the outline, the edge margin and
the obstacles." The roof inside its edge margin, less the obstacles and the area kept clear, holds no module. Press
**Open Roof**, then check the outline, the edge margin and the obstacles' heights.
</Accordion>
<Accordion title="Row spacing &lt;p&gt; m is less than a row's depth plus 0.3 m. The app uses &lt;q&gt; m.">
The row spacing typed is less than a row's depth on plan plus 0.3 m, so the app lays the rows out at the larger
spacing. Type a spacing at least that large, or turn **Row spacing from the shade-free hours** on. See
[Spacing](/docs/rooftop/array#spacing).
</Accordion>
<Accordion title="Unit gap &lt;g&gt; m keeps east-west units free of shade in the shade-free hours.">
On a roof with rows facing east and west, the app leaves a gap between units so they do not shade each other in the
shade-free hours. It is a note, not a fault: the gap follows from the east-west tilt and the shade-free hours.
</Accordion>
<Accordion title="Voc coefficient outside the usual range">
"Usually −0.35 to −0.20 %/°C for this kind of module. Enter the datasheet's value." The module file's Voc coefficient
is unusual, and the longest string depends on it. Type the datasheet's value in the note's field, or in the Strings
step's **Sizing temperatures** ▸ **Voc coefficient**. **Keep &lt;value&gt;** keeps the file's.
</Accordion>
<Accordion title="&lt;file&gt; gives no size of the module (Width and Height). The layout needs it: choose a PAN file that has it.">
The module file has no size, so no module can be placed. Choose a module file that gives its width and height, or a
module from the library. See [Module](/docs/rooftop/array#module).
</Accordion>
<Accordion title="Module not changed">
The module file was refused, and the module of before stays. The reason follows, such as "&lt;file&gt; is not a
module file (PAN): PNom, Voc or Isc is missing." Choose a PVsyst module file that has them. See
[Equipment files](/docs/rooftop/reference#equipment-files).
</Accordion>
<Accordion title="&lt;name&gt; is over 256 KB, larger than any module or inverter file. Choose another.">
The file is too large to be a module or an inverter file. Choose the PAN or OND file itself.
</Accordion>
<Accordion title="The app cannot read the file as text: it is in none of utf-8, latin-1, cp1252. · The file could not be read: &lt;reason&gt;. Choose another.">
The file is not text in a form the app reads, or the browser could not read it. Save the file again as text from
PVsyst, or get the maker's file again, then choose it.
</Accordion>
<Accordion title="The equipment library did not load. · &lt;file&gt; did not load from the library. Try again.">
The library's list, or one of its files, did not come. Press **Try again**, or choose it again.
</Accordion>
<Accordion title="No module in the library matches “&lt;search&gt;”. · No module in the library fits these filters.">
The search or the filters leave no module. Press **Clear the search** or **Clear the filters**, or use your own module
file (PAN).
</Accordion>
</Accordions>

## Sun view and Strings

<Accordions>
<Accordion title="Sun path not updated">
The sun's day did not come back for the place or the day. The light of the day before stays. Press **Try again**.
</Accordion>
<Accordion title="Waits for the run">
The shade map colours the modules once the run is of the layout shown. It fills in when the run lands.
</Accordion>
<Accordion title="Horizon not counted: the weather for this site came without one · Horizon not counted: this weather has none">
The run leaves horizon shading out. The typical year came without the site's horizon this time (a note waits to
review), or the weather is 2023's or a CSV of your own, which bring none. Choose **Typical year** on Performance to
count the horizon. See [Shade over the year](/docs/rooftop/sun#shade-over-the-year).
</Accordion>
<Accordion title="No string length fits at &lt;V&gt; V">
"This inverter needs at least &lt;n&gt; modules in a string. At &lt;V&gt; V a string holds at most &lt;m&gt;." The
inverter's MPPT minimum needs a longer string than the system voltage allows. Press **Choose another inverter** or
**Change the sizing temperatures**. Where a higher voltage fits, the step's button reads **Use &lt;W&gt; V**: check
first that the site's code allows it. See [When no string length fits](/docs/rooftop/strings#when-no-string-length-fits).
</Accordion>
<Accordion title="Too few positions for a string">
The roof's positions are too few for the options the app makes. The message gives how many it holds and the lengths
a string takes, and a length that fits if one does: add it with **Add your own option**.
</Accordion>
<Accordion title="Your stringing no longer fits. Option &lt;letter&gt; is used.">
A change took away the option you had chosen, so the run's first option is used. Press **Undo** to take the change
back, or **Choose another** to open the Strings step.
</Accordion>
<Accordion title="Below the DC/AC target · Above the DC/AC target · Heavy clipping">
The chosen option's DC/AC ratio is under 1.10, between 1.30 and 1.40, or over 1.40. The Strings step is marked to
review it. Choose an option in the target, or change the inverter. See [Options](/docs/rooftop/strings#options).
</Accordion>
<Accordion title="MPPT current over its limit, or the limit not known">
The option is in its DC/AC target, but an MPPT carries more current than its limit, or the inverter file gives no
limit. Open **MPPT loading** to see which. See [MPPT loading](/docs/rooftop/strings#mppt-loading).
</Accordion>
<Accordion title="Current per MPPT not in the inverter file · Not in the OND: IMaxDC &lt;n&gt; A ÷ &lt;m&gt; MPPT. Enter the datasheet value if it differs.">
The file gives no current per MPPT: the app shares the highest DC current among the MPPTs, or knows no limit. Type
the datasheet's value in **Inverter limits and cabling** ▸ **Current per MPPT** (**Enter the current per MPPT** opens it).
</Accordion>
<Accordion title="Inverter not changed">
The inverter file was refused, and the inverter of before stays. The reason follows, such as "&lt;file&gt; is not an
inverter file (OND): PNomConv or VMPPMax is missing." Choose a PVsyst inverter file that has them.
</Accordion>
<Accordion title="A string of &lt;n&gt; does not fit at &lt;V&gt; V · Each inverter needs at least 1 string. Change your option or remove it.">
Your own option does not fit: its modules per string are too many or too few (the detail says the longest or the
shortest that fits, and why), or it has more inverters than strings. Change your option or remove it. See
[Your own option](/docs/rooftop/strings#your-own-option).
</Accordion>
<Accordion title="This inverter takes up to &lt;r&gt; V. Raise it only if the site's code allows.">
The inverter is rated above the system voltage set. The app never raises the voltage. Press **Use &lt;V&gt; V** only
where the site's code allows it.
</Accordion>
<Accordion title="Strings sized to &lt;r&gt; V, this inverter's limit">
The inverter, or the module, is rated under the system voltage, so the strings are sized to its rating. The bill of
materials uses the system voltage. Press **Use &lt;V&gt; V** to set the highest voltage the rating allows. See
[System voltage](/docs/rooftop/strings#system-voltage).
</Accordion>
</Accordions>

## Performance

<Accordions>
<Accordion title="Energy not updated · Showing the last result · Try again">
Under Performance's title: a run failed after one that worked. The figures of before stay, and the failure's words
follow. Press **Try again**. With nothing before, it reads "Energy not computed · There is no result yet".
</Accordion>
<Accordion title="The server could not finish this step. Try again. · The run ended before its result arrived. Try again.">
The server stopped on a fault during the run, or the run's answer was cut short. Press **Try again** under
Performance's title.
</Accordion>
<Accordion title="Weather not loaded">
The weather chosen did not load; the reason follows, and the weather of before stays. For PVGIS or NASA POWER the
reason names the service: it has no weather for the place, it could not be reached, it answered in a form that cannot
be read, or it failed. Check the connection and choose the weather again, or choose another source. See
[Option and weather](/docs/rooftop/performance#option-and-weather).
</Accordion>
<Accordion title="The weather for this site came without a horizon. The run leaves horizon shading out.">
PVGIS gave the typical year without the site's horizon, so the energy leaves horizon shading out. The note waits in
the list to review, under "Weather · Performance".
</Accordion>
<Accordion title="The file is over 3 MB. A year of weather is under 3 MB, even at 15-minute steps. Choose a file of one year.">
The CSV is larger than one year of weather. Choose a file of one year. See
[Weather (CSV)](/docs/rooftop/reference#weather-csv).
</Accordion>
<Accordion title="This file cannot be used">
The CSV was refused; the reason follows in the app's words. The usual ones: "&lt;file&gt;: no column named any of
…" (no time or global irradiance column), "&lt;file&gt; has &lt;n&gt; hours. A year has 8,760, a leap year 8,784.
Give a whole year.", a time that cannot be read ("Write it as 2023-06-01 13:00, in UTC."), an hour given twice ("Keep
each hour once."), or an empty irradiance cell ("Fill the gaps in the irradiance column."). Correct the file, then
choose it again.
</Accordion>
<Accordion title="The file was not loaded">
The CSV could not be sent or read: the server could not be reached, did not answer, or the app stopped on a fault.
The cause and what to do follow. Check the connection, then choose the file again.
</Accordion>
<Accordion title="&lt;file&gt; has no beam and diffuse irradiance.">
A note on a CSV read: the app works the beam and the diffuse out from the global irradiance (Erbs model), less
exactly than a measurement. Other notes say the file has no air temperature (25 °C is taken), no wind (1 m/s), steps
shorter than an hour (averaged), irradiance below zero (taken as 0) or gaps in the temperature (filled). With no air
temperature, enter the site's lowest and highest ambient on the Strings step.
</Accordion>
<Accordion title="The module is not bifacial: no rear gain. · Flush modules lie on the roof: no rear gain.">
**Bifacial rear gain** cannot be used: the module is not bifacial, or the roof is **Sloped**. Nothing to do.
</Accordion>
</Accordions>

## Handover and Present

A download that fails says why in a toast, in the server's words, with **Try again**. While a file is on its way, the
browser asks before the page is left.

<Accordions>
<Accordion title="Files not made · Files not updated">
The run failed, so the files cannot be made. After a first run that failed, each waiting row reads "Not made"; after
one that worked, the files of before stay, marked "Showing the last result". The project file can still be
downloaded. Press **Try again**. See [When a file is not made](/docs/rooftop/handover#when-a-file-is-not-made).
</Accordion>
<Accordion title="Pages not made · Pages not updated · Hourly data not made">
The report's pages, or the hourly data, did not come for the preview; pages of before stay, dimmed. Press
**Try again**.
</Accordion>
<Accordion title="No module fits on this roof · No string length fits at &lt;V&gt; V · Too few positions for a string">
A row's line reads the reason the design has no option, and its file cannot be made. Press **Open Strings** (or
**Open Roof**, when no module fits) in the preview, put it right there, and come back.
</Accordion>
<Accordion title="The table could not be copied. Select it and copy by hand.">
The browser refused **Copy**. Select the table and copy it with the browser's own copy.
</Accordion>
<Accordion title="Over 1 % even at 10 mm². Shorten the run or move the inverter nearer.">
In the cable schedule, a string's voltage drop is over 1 % even at the largest cable size. Shorten the run, or put
the inverter nearer its strings.
</Accordion>
<Accordion title="Updating energy">
At the foot of Present: a run is on its way, and the tour starts when it lands. The no-options title stands there
instead when the design has no option: put it right on the Roof or the Strings step. See [Present](/docs/rooftop/present).
</Accordion>
</Accordions>
